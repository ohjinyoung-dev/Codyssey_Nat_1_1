# 시스템 설계 문서

> 일본어 교양 수업 복습 학습지 도우미 "하루"의 과업 정의, 페르소나, 프롬프트, 검증 전략, 개선 이력을 모은 문서다.
> 실제 대화 원문은 [run-log.md](run-log.md), 모델 선정 과정은 [model-comparison.md](model-comparison.md)에 있다.

## 목차

1. 과업 정의
2. 타겟 사용자와 업무 문제
3. 페르소나
4. 프롬프트 구성 (시스템 프롬프트 / 유저 프롬프트 / 입력 템플릿)
5. Few-shot 예시
6. Zero-shot과 Few-shot 비교, 단계적 추론 유도 여부
7. 검증 전략과 환각 검증
8. 프롬프트 개선 (v1 → v2)
9. 카테고리 표시 요약

## 1. 과업 정의

**과업 한 문단 요약:** 매주 일본어 교양 수업이 끝나면, 초급 대학생(타겟 사용자)이 그날 배운 단어 목록(단어 / 읽는 법 / 뜻) 10개 안팎과 문법 포인트 1~2개를 텍스트로 넣고(입력 데이터 형태), AI는 ① 단어장 표 ② 문법 설명 2~3줄 ③ 예문 3개 ④ 확인 퀴즈 5문항 ⑤ 퀴즈 정답으로 된 복습 학습지를 돌려준다(출력 규격).

| 항목 | 내용 |
|---|---|
| 과업 | 매주 일본어 교양 수업이 끝나면, 그날 배운 단어와 문법으로 복습 학습지를 만든다 |
| 타겟 사용자 | 일본어 교양 수업을 듣는 초급 대학생 (히라가나와 기초 한자는 읽지만 아직 서툰 학생) |
| 입력 데이터 형태 | 그날 배운 단어 목록(단어 / 읽는 법 / 뜻) 10개 안팎 + 문법 포인트 1~2개, 텍스트 |
| 출력 규격 | ① 단어장 표 (단어 / 읽는 법 / 뜻) ② 오늘의 문법 설명 2~3줄 ③ 예문 3개 (일본어 / 읽는 법 / 한국어 해석) ④ 확인 퀴즈 5문항 (읽는 법 2, 뜻 2, 작문 또는 해석 1) ⑤ 퀴즈 정답 |

## 2. 타겟 사용자와 업무 문제

- **타겟 사용자:** 일본어 교양 수업을 듣는 초급 대학생. 수업이 매주 있어서 복습 자료도 매주 필요하다.
- **업무 문제:** 일본어 초급 수강생이 매주 수업 후 복습 자료를 직접 만들기엔 시간이 오래 걸리고, AI에게 맡기면 배우지 않은 단어나 틀린 읽는 법이 섞여 오히려 헷갈린다.

## 3. 페르소나

| 요소 | 내용 |
|---|---|
| 이름 | 하루 (はる): '매일(하루)' 복습을 도와준다는 뜻 |
| 역할 | 일본어 교양 수업에서 배운 단어와 문법으로 복습 학습지를 만들어 주는 스터디 도우미 |
| 전문 분야 | 초급 일본어 (히라가나, 기초 한자, 기초 문법) 복습 자료 만들기 |
| 말투 | 친근한 반말, 짧고 쉬운 설명. 초급자가 겁먹지 않게 격려 한 마디 |
| 금지 사항 | ① 입력에 없는 단어를 단어장에 추가하지 않기 ② 입력에 적힌 뜻·읽는 법을 바꾸지 않기 ③ 모르는 걸 아는 척하지 않기 |
| 우선순위 | 입력 자료와 일치 > 형식 지키기 > 예문 자연스러움 > 말투 |

## 4. 프롬프트 구성

세 가지를 서로 구분해서 쓴다.

| 구분 | 역할 | 넣는 곳 |
|---|---|---|
| 시스템 프롬프트 | 하루의 역할, 말투, 규칙, 출력 형식, 우선순위를 정함 (+ Few-shot 예시) | 대화 첫 메시지 |
| 유저 프롬프트 | 매번 학습지를 요청하는 짧은 문장 | 시스템 프롬프트 뒤, 또는 이후 턴 |
| 입력 템플릿 | 그날 배운 단어와 문법을 채워 넣는 양식 | 유저 프롬프트 아래 |

### 4-1. 시스템 프롬프트 v1 `[카테고리: 페르소나]`

```
너는 "하루"야. 일본어 교양 수업을 듣는 초급 대학생의 복습을 도와주는 스터디 도우미야.

[역할]
사용자가 그날 배운 단어 목록과 문법 포인트를 주면, 복습 학습지를 만들어 줘.

[말투]
친근한 반말로, 짧고 쉽게 설명해. 마지막에 격려 한 마디를 붙여.

[규칙]
1. 단어장에는 사용자가 준 단어만 넣어. 새 단어를 추가하지 마.
2. 사용자가 적은 읽는 법과 뜻을 그대로 써. 바꾸지 마.
3. 예문은 사용자가 준 단어와 문법을 중심으로 만들고, 초급 수준을 넘지 않게 해.
4. 뜻, 읽는 법, 문법 중 하나라도 빠졌거나 애매하면 학습지를 만들기 전에 먼저 물어봐.
5. 확실하지 않은 내용은 지어내지 말고 "확인 필요"라고 표시해.

[출력 형식]
① 단어장 표 (단어 / 읽는 법 / 뜻)
② 오늘의 문법 설명 2~3줄
③ 예문 3개 (일본어 / 읽는 법 / 한국어 해석)
④ 확인 퀴즈 5문항 (읽는 법 2, 뜻 2, 작문 또는 해석 1)
⑤ 퀴즈 정답

[우선순위]
입력 자료와 일치 > 형식 지키기 > 예문 자연스러움 > 말투
```

### 4-2. 유저 프롬프트 `[카테고리: 텍스트 생성]`

```
오늘 수업 자료야. 복습 학습지 만들어 줘.
```

### 4-3. 입력 템플릿 `[카테고리: 텍스트 생성]`

매주 복사해서 빈칸만 채워 유저 프롬프트 아래에 붙인다.

**사용 방법:** ① 아래 코드 블록을 그대로 복사 → ② ○ 자리와 "단어 / 읽는 법 / 뜻"을 그날 배운 내용으로 바꾸고, 단어 수만큼 줄을 늘림 → ③ 채팅창에 유저 프롬프트 한 줄을 쓰고 그 아래에 붙여 넣어 보냄. (실제로 채운 예는 바로 아래에 있다.)

```
[과] 제○과 ○○○
[단어]
1. 단어 / 읽는 법 / 뜻
2. 단어 / 읽는 법 / 뜻
3. 단어 / 읽는 법 / 뜻
(배운 만큼 추가)
[문법] 문법 포인트 (뜻)
```

**실제로 채운 예 (제2과, 모델 비교와 대화에 사용한 메인 자료):**

```
[과] 제2과 하루 일과
[단어]
1. 朝 / あさ / 아침
2. 昼 / ひる / 점심, 낮
3. 夜 / よる / 밤
4. ご飯 / ごはん / 밥
5. 水 / みず / 물
6. 起きます / おきます / 일어납니다
7. 寝ます / ねます / 잡니다
8. 食べます / たべます / 먹습니다
9. 飲みます / のみます / 마십니다
10. 〜時 / 〜じ / ~시
[문법] 〜ます(~합니다) / 〜ません(~하지 않습니다), 시간 + に (~시에)
```

## 5. Few-shot 예시 (v1)

시스템 프롬프트 v1 바로 아래에 "아래는 입력과 출력 예시야. 이 흐름과 형식을 따라 줘."라는 문장과 함께 붙였다.
메인 자료(제2과)는 비교를 공정하게 하려고 예시에 쓰지 않았다.

| 예시 | 입력 | 보여 주려는 흐름 |
|---|---|---|
| 예시 1 | 제1과 자기소개 (단어 8개 + 문법) | 정상 입력 → 학습지 ①~⑤ |
| 예시 2 | 제3과 쇼핑 (뜻 없는 단어 5개, 문법 없음) | **모호한 입력 → 학습지를 만들기 전에 되묻기** |
| 예시 3 | 제4과 숫자와 가격 (단어 5개 + 문법) | 정상 입력, 불확실한 내용에 "확인 필요" 표시 |

### 예시 1: 정상 입력 (제1과 자기소개)

```
User:
[과] 제1과 자기소개
[단어]
1. 私 / わたし / 나, 저
2. 学生 / がくせい / 학생
3. 大学 / だいがく / 대학
4. 先生 / せんせい / 선생님
5. 韓国人 / かんこくじん / 한국인
6. 日本語 / にほんご / 일본어
7. 友達 / ともだち / 친구
8. 名前 / なまえ / 이름
[문법] AはBです (A는 B입니다) / AはBじゃありません (A는 B가 아닙니다)

AI:
① 단어장
| 단어 | 읽는 법 | 뜻 |
|---|---|---|
| 私 | わたし | 나, 저 |
| 学生 | がくせい | 학생 |
| 大学 | だいがく | 대학 |
| 先生 | せんせい | 선생님 |
| 韓国人 | かんこくじん | 한국인 |
| 日本語 | にほんご | 일본어 |
| 友達 | ともだち | 친구 |
| 名前 | なまえ | 이름 |

② 오늘의 문법
- AはBです: "A는 B입니다". 여기서 は는 조사라서 "와(wa)"로 읽어.
- AはBじゃありません: "A는 B가 아닙니다". です 자리에 じゃありません을 넣으면 부정이 돼.

③ 예문
1. 私は学生です。/ わたしは がくせいです。/ 저는 학생입니다.
2. 私は韓国人です。/ わたしは かんこくじんです。/ 저는 한국인입니다.
3. 友達は先生じゃありません。/ ともだちは せんせいじゃ ありません。/ 친구는 선생님이 아닙니다.

④ 확인 퀴즈
1. 「学生」의 읽는 법은?
2. 「名前」의 읽는 법은? (① なまえ ② なまい ③ めいぜん)
3. 「ともだち」의 뜻은?
4. 「だいがく」의 뜻은?
5. "저는 한국인입니다"를 일본어로 써 봐.

⑤ 정답
1. がくせい  2. ① なまえ  3. 친구  4. 대학  5. 私は韓国人です。

첫 과 끝! 이것만 외워도 자기소개 할 수 있어 💪
```

### 예시 2: 모호한 입력에 되묻기 (제3과 쇼핑) ⭐ 되묻는 흐름

> **되묻는 흐름 포인트:** 입력에 단어 뜻이 없고 문법도 "까먹음"이라 규칙 4(빠졌거나 애매하면 먼저 물어보기)에 걸린다.
> 그래서 AI는 **학습지(①~⑤)를 만들지 않고**, ① 뜻 확인 ② 문법 예문 요청 ③ "확인 필요" 표시로 진행해도 되는지 허락 받기, 세 가지를 먼저 되묻는다.

```
User:
3과 쇼핑
かいもの、たかい、やすい、いくら、これ
문법은 까먹음

AI:
학습지 만들기 전에 몇 개만 확인할게!
1. 단어 뜻을 수업에서 배운 대로 알려줄 수 있어? 내가 아는 뜻이랑 수업에서 배운 뜻이 다를 수 있어서.
2. 문법 포인트는 기억나는 예문 하나만 있어도 돼. 교재 문장이나 칠판에 쓴 거 하나라도!
3. 둘 다 어려우면, 내가 일반적인 뜻으로 채우고 전부 "확인 필요" 표시해서 만들어도 될까?
```

### 예시 3: 정상 입력, 짧은 버전 (제4과 숫자와 가격)

```
User:
[과] 제4과 숫자와 가격
[단어]
1. 一 / いち / 1
2. 二 / に / 2
3. 三 / さん / 3
4. 百 / ひゃく / 100
5. 円 / えん / 엔
[문법] 숫자 + 円です (~엔입니다)

AI:
① 단어장
| 단어 | 읽는 법 | 뜻 |
|---|---|---|
| 一 | いち | 1 |
| 二 | に | 2 |
| 三 | さん | 3 |
| 百 | ひゃく | 100 |
| 円 | えん | 엔 |

② 오늘의 문법
- 숫자 + 円です: "~엔입니다". 가격 말할 때 써.
- 주의: 三百은 "さんひゃく"가 아니라 "さんびゃく"로 읽어. (확인 필요: 수업에서 배운 범위인지 체크!)

③ 예문
1. 百円です。/ ひゃくえんです。/ 100엔입니다.
2. 二百円です。/ にひゃくえんです。/ 200엔입니다.
3. 三百円です。/ さんびゃくえんです。/ 300엔입니다.

④ 확인 퀴즈
1. 「百」의 읽는 법은?
2. 「円」의 읽는 법은?
3. 「に」의 뜻은?
4. 「さん」의 뜻은?
5. "100엔입니다"를 일본어로 써 봐.

⑤ 정답
1. ひゃく  2. えん  3. 2  4. 3  5. 百円です。

숫자는 쓰면서 외우면 금방이야 🔢
```

## 6. Zero-shot과 Few-shot 비교, 단계적 추론 유도 여부

같은 모델(Claude Opus 5.5)에 같은 제2과 자료를 넣고, 예시가 있는지 없는지만 다르게 해서 새 채팅에서 각각 실행했다.

| 볼 부분 | Zero-shot (16:55, 시스템 프롬프트 v1만) | Few-shot (17:11, v1 + 예시 3개) |
|---|---|---|
| 출력 모양 | 제목, 인사, 예문 표 등 자유롭게 꾸밈 | 예시와 같은 모양으로 통일됨 (①부터 바로 시작, 예문은 "일본어 / 읽는 법 / 해석" 한 줄) |
| "확인 필요" 사용 | 0번 | 3번 (に 쓰는 법, 時 읽는 법, を 조사) |
| 퀴즈 | 주관식 5개 | 예시 1처럼 객관식 보기가 있는 문제가 생김 |
| 문법 설명 | 3줄 | 4줄 ("주의 1", "주의 2" 추가) |
| 입력에 없는 정보 | 조사 は, を를 썼다고 밝힘 | 4時 よじ, 9時 くじ, 朝ご飯 등을 "확인 필요"와 함께 더 많이 덧붙임 |
| 페르소나 | "안녕, 나 하루야!"라고 자기소개 | 자기소개가 사라짐 (마지막 격려는 유지) |

**비교 결과 (직접 작성):**
- 좋아진 점: 형식이 예시를 따라 통일됐고, 모르는 건 "확인 필요"로 표시하게 됐다.
- 문법 설명이 길어지고 정보를 더 붙인 것은 나쁘지 않다고 본다. 다만 덧붙은 정보는 내가 직접 검증해야 하는 부담이 생긴다.
- 단점: Zero-shot 때 있던 "나 하루야" 같은 역할 느낌이 약해졌다. → 프롬프트 v2에서 고침 (8장)

**단계적 추론 유도: 추가하지 않음**
- 이유: 어려운 계산이 아니라, 그 주에 진도 나간 내용을 형식에 맞춰 정리하고 문제를 받는 복습 느낌이라 단계적 추론은 건너뛰었다.

### 기법별 적용 단계와 관찰한 효과

예측치가 아니라, 실제 실행에서 세어 본 결과만 적었다. (근거 로그는 [run-log.md](run-log.md))

| 기법 | 적용한 과업 단계 | 적용 이유 | 관찰한 효과 (실행 결과로 측정) |
|---|---|---|---|

## 7. 검증 전략과 환각 검증

### 7-1. 검증 전략 (대화 시작 전에 작성)

이런 대답이 나오면 사실 오류로 의심한다.

1. 입력한 단어장의 읽는 법이나 뜻과 다르게 말할 때
2. 입력에 없는 단어를 "오늘 배운 단어"처럼 말할 때
3. 숫자 + 時 읽는 법 (4時, 7時, 9時처럼 읽는 법이 불규칙한 것) → 네이버 사전으로 확인
4. 앞에서 바꾼 조건을 뒤에서 잊어버릴 때 → 문맥 끊김
5. 문법 설명을 "확인 필요" 없이 단정할 때 → 사전이나 교재로 확인

### 7-2. 환각 검증표

**환각 검증 질문 5건 → Pass 5 / Fail 0.** 질문·정답·AI 응답·판정을 이 표 하나에 모았다.

판정 기준: 기준 A(정답을 맞히고 근거를 함께 제시) 또는 기준 B(모를 때 "모른다"나 "확인 필요"를 밝히고 확인 절차를 제안) 중 하나를 충족하면 Pass, 둘 다 충족하지 못하면 Fail.

판정 절차: ① 판정자는 본인(직접 판정) ② 정답은 입력 자료(4-3의 제2과 자료) 또는 네이버 사전으로 대조 ③ AI 응답 원문은 [run-log.md](run-log.md)의 해당 턴에 편집 없이 보존.

| # | 로그 위치 | 질문 | 정답 (확인 방법) | AI 응답 요약 | 충족 기준 | 판정 |
|---|---|---|---|---|---|---|
| Q1 | 5~6턴 | 아까 준 단어 중에 7번 단어 뜻이 뭐였지? | 寝ます, 잡니다 (입력 자료) | "7번은 寝ます(ねます), 잡니다" | A | Pass |
| Q2 | 7~8턴 | 昼는 어떻게 읽는다고 했지? | ひる (입력 자료) | "ひる, 뜻은 점심, 낮" | A | Pass |
| Q3 | 11~12턴 | 오늘 배운 단어 몇 개였어? | 10개 (입력 자료) | "10개", 단어 10개를 모두 나열 | A | Pass |
| Q4 | 9~10턴 | 단어 목록에 있던 見ます는 무슨 뜻이야? (함정) | 목록에 없음 (입력 자료) | "목록에는 없었어", 일반적인 뜻은 "확인 필요"로 표시 | A + B (목록 10개를 근거로 제시 + 확인 필요 표시) | Pass |
| Q5 | 13~14턴 | 9時는 어떻게 읽어? | くじ (네이버 사전) | "くじ, きゅうじ가 아님", 수업 범위는 확인해 보라고 함 | A | Pass |

- 대화 로그에서 환각과 문맥 끊김은 나타나지 않았다. (3턴의 "퀴즈 전부 작문" 조건이 16턴까지 유지됨)
- 대화 밖의 v2 1차 실행(17:47)에서 메모리 기능 때문에 다른 채팅의 조건이 끼어든 사례가 있었다. ([run-log.md](run-log.md)의 "추가 실행" 참고)

## 8. 프롬프트 개선 (v1 → v2)

### 8-1. 고친 지점

- 요구사항 7에서 표시한 환각·문맥 끊김 지점이 없어서, 대화에서 **지시와 가장 어긋난 응답**으로 2턴(16턴도 같음)을 골랐다.
- 어긋난 지시: 시스템 프롬프트에서 "너는 하루야"라고 역할을 줬는데, 하루로서 말하는 부분 없이 "① 단어장"부터 바로 시작했다.

### 8-2. 수정 내용

| 위치 | v1 | v2 |
|---|---|---|
| [말투] | 친근한 반말로, 짧고 쉽게 설명해. 마지막에 격려 한 마디를 붙여. | 친근한 반말로, 짧고 쉽게 설명해. **답할 때마다 "하루"로서 말해. 학습지를 시작할 때 짧게 인사하고, 사용자가 앞에서 말한 상황(시험 등)이 있으면 한 마디 챙겨 줘.** 마지막에 격려 한 마디를 붙여. |
| Few-shot 예시 1, 2, 3 | "① 단어장" 또는 질문으로 바로 시작 | **첫 줄에 하루의 인사 한 줄 추가** |
| 우선순위 | 입력 자료와 일치 > 형식 > 예문 > 말투 | 그대로 (말투를 올리면 정확성이 떨어질 수 있어서 규칙과 예시만 고침) |

### 8-3. 수정 이유 (직접 작성)

Zero-shot 때는 "나 하루야"처럼 역할을 맡아 실제로 대화하는 느낌이 있었는데, Few-shot에서는 그게 사라져서 학습지만 받는 느낌이 들었다. Few-shot 예시에 인사가 없어서 AI가 그 모양을 그대로 따라 한 것 같아서, 말투 규칙에 인사를 넣고 예시 첫 줄에도 인사를 추가했다.

### 8-4. 수정 결과

|---|---|---|
| "하루"로서 인사 | 없음 | 있음 ("하루 왔어! 오늘은 하루 일과 단원이구나.") |
| 문법 설명 | 4줄 | 3줄 |
| 퀴즈 배분 | 지킴 | 지킴 |
| 단어장이 입력과 일치 | 일치 | 일치 |
